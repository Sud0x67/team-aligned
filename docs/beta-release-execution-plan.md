# Beta 发布执行计划（执行版）

更新时间：2026-04-24

## 目标

在不新增产品大功能的前提下，尽快收敛到一个可发布、可验证、可回归的 beta 版本。

## 发布门槛（必须全部满足）

- 聊天主链路稳定：单聊、群聊、@、handoff、流式过程反馈
- 通知链路稳定：前台/后台行为正确，权限引导可用
- Provider 错误与恢复路径一致
- 至少具备最小可用导出与备份说明
- 具备最小自动化验证（typecheck/lint/build + 关键烟测）
- 能稳定打包并完成安装体验检查

## 执行分期

### 第 1 期：发布基线（已开始）

目标：先把“每次变更都可验证”的底座补齐。

任务：

- [x] 新增关键烟测：slash 命令解析
- [x] 新增关键烟测：群聊执行批次（并行/串行/依赖/冲突）
- [x] 新增一键发布前检查脚本：`npm run beta:check`
- [x] 将烟测扩展到 `@` 指定与 handoff 连续轮

验收：

- `npm run beta:check` 可在本地通过
- 烟测覆盖当前最易回归的核心逻辑

### 第 2 期：聊天与群聊体验收口（P0）

目标：让用户在群聊中感受到“持续在工作”，不是“卡住”。

任务：

- [x] 群聊过程消息策略统一（开始、等待、执行中、完成、失败）
- [x] 明确依赖等待文案，减少“静默等待”
- [x] `@` 命中、无命中、跨轮接棒做回归修边
- [x] 流式输出与思考态保持单一来源，杜绝重复气泡

验收：

- 5 组真对话回放场景可稳定复现并通过
- 无“已执行但无过程反馈”卡顿感

### 第 3 期：通知与 Provider 可靠性（P0）

目标：减少“能用但不敢用”的不确定感。

任务：

- [x] 通知触发策略收口为统一函数并补烟测
- [x] Provider 连接测试/保存/聊天失败三处错误语义统一（程序侧）
- [x] Provider 典型供应商错误格式归一（含 `incorrect_api_key_error` / `Troubleshooting URL`）
- [x] 第 3 期实机验收清单文档补齐
- [x] 通知前后台行为实机复测并回填结果
- [x] 点击系统通知回会话路径复测并回填结果
- [x] 常见超时与取消提示语继续细化（含 Provider 与 MCP 超时/鉴权/网络提示）

验收：

- 通知策略与设置项 1:1 对齐
- Provider 常见失败能给出可操作提示

### 第 4 期：导出、备份、检索最小可用（P1）

目标：给 beta 用户可带走、可恢复的数据能力。

任务：

- [x] 最小会话导出（会话 + 消息 + runs + artifacts + attachments 索引）
- [x] `~/.teamaligned` 备份与恢复文档固化
- [x] 会话公开消息本地检索入口最小可用
- [ ] transcript / artifact 专门检索入口最小可用

验收：

- 一次导出可复核当前会话关键数据
- 文档可指导用户做本地备份

### 第 5 期：发布收尾（P1）

目标：形成可重复执行的发版动作。

任务：

- [x] 打包配置最终核对（`dist:mac`）
- [ ] 安装包体验检查（安装、启动、首次配置、聊天）
- [x] 发布 checklist 与已知限制（Known Issues）

验收：

- 发布流程可按文档重复执行
- 关键链路无阻断问题
