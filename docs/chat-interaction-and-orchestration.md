# 聊天交互与编排规范

## 文档目标

这份文档专门定义 `teamaligned` 中最核心的交互层：

- 单聊如何工作
- 群聊如何工作
- slash command 如何工作
- 复杂任务如何暂停 / 恢复 / 取消
- 多 Agent 如何通信

## 1. 单聊交互模型

单聊是用户与单个 Agent 的直接协作线程。

### 支持的输入类型

单聊至少支持四类输入：

- 自然语言
- slash command
- 附件
- 运行控制

### Slash Command

第一版正式支持以下命令：

- `/skills`
- `/command`
- `/mcp`
- `/pause`
- `/resume`
- `/cancel`

### 当前输入框策略

当前 UI 已确定采用“极简输入区”：

- 不在输入框上方常驻展示 `/skills /command /mcp` 快捷 chips
- 用户通过直接输入 slash command 触发命令
- 输入区只保留文本框、附件按钮、`@` 按钮、命令按钮和发送按钮

这么做的目的不是降低命令能力，而是减少会话页的视觉碎片。

### 后续可补的增强

- 用户输入 `/` 时弹出命令建议
- 输入 `/skills` 时展示已安装 skills
- 输入 `/mcp` 时展示已安装 MCP 服务
- 输入 `/command` 时提示本地命令会在当前 workspace 中执行

### 单聊中的复杂任务

当前实现中，当任务进入复杂执行态时，输入框上方会出现运行控制按钮，支持：

- 暂停
- 继续
- 取消

后续可以再补：

- 查看 run 详情
- 查看 checkpoint
- 查看产物与日志

## 2. 群聊交互模型

群聊是用户、manager agent 和多个 specialist agent 的统一协作线程。

### 群聊中的发言主体

群聊主线程可出现：

- 用户消息
- manager agent 消息
- specialist agent 消息
- 系统消息
- 提及消息

### 群聊中的 `@`

群聊必须支持：

- 用户 `@agent`
- Agent `@agent`
- Agent `@user`

建议行为：

- `@` 输入时弹出群组成员选择面板
- 被提及时生成消息内高亮与通知
- manager 可以通过 `@frontend` 这类形式显式调度 specialist

### Agent 之间通信

Agent 间通信分为两种：

#### 公开协作

直接显示在群聊主线程中。

示例：

- `Designer @Frontend：新版原型已上传，请开始还原`
- `Backend @QA：接口联调已准备好，请开始验证`

#### 内部协作

默认不完整展示给用户，只在 run 详情展开。

当前实现中，内部协作消息默认隐藏，通过会话头部的“显示内部协作”开关控制显隐。

示例：

- manager 给 specialist 分配子任务
- 一个 specialist 将工具结果发给另一个 specialist

## 3. 群组上下文模型

每个 Agent 在群聊中都必须知道当前群组上下文。

群组上下文至少包含：

- 群组目标
- 成员与角色
- 最近消息摘要
- 当前任务列表
- 当前活跃 run
- 共享 memory
- 共享 workspace 摘要
- 已产出的关键 artifacts

### 上下文刷新时机

建议在以下时机刷新群组上下文：

- 用户发送新任务
- 新子任务被分配
- 某个 Agent 完成阶段性产出
- 运行恢复
- 群组共享记忆更新

## 4. 复杂任务控制模型

复杂任务应始终对应一个可追踪的 run。

### Run 状态

建议状态包括：

- 排队中
- 运行中
- 暂停中
- 已暂停
- 恢复中
- 已完成
- 已失败
- 已取消

### 暂停语义

第一版采用协作式暂停：

- 不再调度新的 step
- 尽量在当前 step 边界停下
- 为恢复记录 checkpoint

### 恢复语义

恢复时从最近 checkpoint 继续，而不是完全重新开始。

### 取消语义

取消后：

- 停止当前 run
- 保留已完成消息与产物
- 在会话中写入取消事件

## 5. UI 建议

### 单聊

当前已落地：

- 当前运行控制条
- 极简输入区
- 命令按钮与 `@` 入口

后续建议补充：

- slash command 自动补全
- 当前 workspace 标识
- 命令执行的结构化结果卡片

### 群聊

当前已落地：

- 群组内部协作显隐开关
- 提及高亮
- 公开协作消息

后续建议补充：

- 群组目标摘要
- 当前活跃成员
- 群组上下文抽屉
- 内部协作详情入口

## 6. MVP 建议边界

为了控制复杂度，MVP 对这套交互的落地建议如下：

### MVP 必做

- 单聊支持 `/skills`、`/command`、`/mcp`
- 单聊支持 run 暂停 / 恢复 / 取消
- 群聊支持用户 `@agent`
- 群聊支持 Agent 公开互相 `@`
- 群聊支持共享上下文摘要

### 后续版本再做

- 内部协作线程完整可视化
- 更细粒度的抢占式暂停
- 并行多 run 调度界面
- 群组上下文的自动压缩与长期记忆融合
