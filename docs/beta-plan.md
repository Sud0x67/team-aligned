# Beta 计划

## 阶段目标

当前阶段最重要的目标，不是继续增加 feature，而是产出一个**真正能让用户使用的 beta 版本**。

这一阶段只围绕 3 件事展开：

1. 完善现有功能的用户使用链路
2. 修复用户使用链路上的体验问题和 bug
3. 清理现有代码中的中间产物，保持代码简洁、稳定、可维护

## 阶段原则

- 不新增新的产品 feature
- 优先保证主链路可用、易懂、稳定
- 优先处理阻断用户完成任务的问题
- 优先删除过渡逻辑、重复逻辑和过时实现

## Beta 前必须跑通的主链路

### 1. 首次启动链路

目标：

- 用户第一次打开应用时不会迷失
- 本地目录、配置和空状态都清晰可理解

需要保证：

- `~/.teamaligned` 初始化稳定
- 默认数据和空状态正确
- 首次没有 provider 时有明确引导

### 2. Provider 配置链路

目标：

- 用户可以独立完成模型配置

需要保证：

- 选择 provider
- 填写 Base URL / API Key / 模型
- 测试连接
- 保存并启用
- 失败时拿到明确、可操作的错误提示

### 3. 单聊链路

目标：

- 用户可以在不学习系统架构的前提下完成一次真实任务

需要保证：

- 创建或选择 Agent
- 发送自然语言消息
- 流式查看回复
- 触发工具、命令、Skill 或 MCP
- 查看结果、artifact、attachment、run 详情

### 4. 群聊链路

目标：

- 用户可以完成一次真实的多 Agent 协作任务

需要保证：

- 创建或选择群组
- 发送任务
- manager 和 specialist 正常协作
- 失败时可理解、可恢复
- run 过程和结果清晰可见

### 5. Skill 链路

目标：

- 用户能够真正安装并用起来一个 Skill

需要保证：

- 同步 catalog
- 安装 Skill
- 配置 Agent 白名单
- 在会话中激活
- 用户能感知 Skill 已经生效

### 6. MCP 链路

目标：

- 用户能够完成一次 MCP 的配置、检测与真实调用

需要保证：

- 同步 catalog
- 配置连接
- 健康检查
- 配置 Agent / Team 白名单
- 在会话中被真实调用
- 失败时给出明确提示

### 7. 附件链路

目标：

- 用户上传的文件真正成为会话的一部分

需要保证：

- 上传成功
- 在消息流中预览
- 文件真实落盘
- 后续可被 Agent 引用

## 当前阶段的核心工作

### A. 用户链路完善

这部分要解决“功能存在，但用户不知道怎么顺畅完成任务”的问题。

重点包括：

- 首次启动与空状态引导
- Provider 配置链路顺滑化
- 单聊与群聊主流程去掉断点
- Skill / MCP / 附件链路上的状态反馈补齐
- run 详情、artifact、attachment、tool invocation 的查看路径清晰化

### B. 体验问题与 bug 修复

这部分要解决“用户能做，但做得不放心”的问题。

重点包括：

- 群聊复杂任务稳定性
- 流式输出异常中断
- run 状态与按钮状态不同步
- provider / MCP / Skill 配置后的状态不一致
- 错误提示难懂、恢复路径不清楚
- artifact、memory、transcript 之间跳转不顺

建议所有问题都按下面三类标记：

- `blocking`：阻断主链路
- `trust`：影响用户对产品可靠性的判断
- `polish`：不阻断，但影响体验

### C. 代码清理与结构收口

这部分要解决“代码能跑，但越来越难维护”的问题。

重点包括：

- 删除中间过渡逻辑
- 删除过时文档和过时注释
- 收口重复状态和重复映射
- 收口旧 payload 兼容访问方式
- 拆分过大的组件与运行时分支
- 统一命名、目录职责和错误处理方式

## 建议执行顺序

### 第 1 阶段：用户链路审查

逐条走完这几条链路并记录问题：

- 首次启动
- Provider 配置
- 单聊
- 群聊
- Skill
- MCP
- 附件

### 第 2 阶段：主链路问题修复

优先修：

- 阻断用户完成任务的问题
- 会导致状态错乱的问题
- 会导致失败不可恢复的问题

### 第 3 阶段：体验打磨

重点补：

- 错误提示
- 恢复路径
- 空状态
- 结果展示
- 可理解性

### 第 4 阶段：代码清理

重点做：

- 删除中间产物
- 删除过期实现
- 清理重复逻辑
- 收口文档与代码口径

### 第 5 阶段：Beta 收尾

重点做：

- 导出能力
- 测试
- 打包
- 发布前 checklist

## Beta 验收标准

当下面这些项全部成立时，可以认为当前版本进入 beta：

- 用户可以独立完成 provider 配置
- 用户可以完成一次单聊真实任务
- 用户可以完成一次群聊协作任务
- 用户可以安装并使用一个 Skill
- 用户可以配置并调用一个 MCP
- 附件可以上传、预览、落盘并参与会话
- 主要失败场景都有明确提示和恢复路径
- 不存在明显空白页、卡死、状态错乱
- 关键代码已经收口，不再依赖大量中间逻辑

## 当前明确不做的事

为了保证 beta 可交付，当前阶段不继续推进：

- 新的页面
- 新的 provider
- OAuth 型 MCP
- 大规模扩展 marketplace 能力
- 与 beta 主链路无关的新功能探索
